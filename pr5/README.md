## Часть 1. Ручной счёт

### 1. Система `3x + y = 5; x + 4y = 9`

* **Проверка диагонального преобладания:**
  * Первая строка: $|3| > |1| \implies 3 > 1$ (выполняется).
  * Вторая строка: $|4| > |1| \implies 4 > 1$ (выполняется).
  * Условие сходимости выполнено.

* **Удобный вид:**
  $$x = \frac{5 - y}{3}, \qquad y = \frac{9 - x}{4}$$

* **Три итерации из старта $(0; 0)$ (округление до 3 знаков):**
  * **Итерация 1:**
    $$x_1 = \frac{5 - 0}{3} \approx 1,667$$
    $$y_1 = \frac{9 - 1,667}{4} = \frac{7,333}{4} \approx 1,833$$
  * **Итерация 2:**
    $$x_2 = \frac{5 - 1,833}{3} = \frac{3,167}{3} \approx 1,056$$
    $$y_2 = \frac{9 - 1,056}{4} = \frac{7,944}{4} = 1,986$$
  * **Итерация 3:**
    $$x_3 = \frac{5 - 1,986}{3} = \frac{3,014}{3} \approx 1,005$$
    $$y_3 = \frac{9 - 1,005}{4} = \frac{7,995}{4} \approx 1,999$$

* **Оценка отклонения:** Точное решение — $(1; 2)$. На старте отклонение составляло $(1; 2)$, а после трёх итераций оно уменьшилось до $0,005$ по $x$ и $0,001$ по $y$ (ошибка сократилась в 200–2000 раз).

### 2. Рабочая система: 2-я итерация из $(1,8; 2,14; 2,892)$

* **Расчёт (с использованием свежих значений внутри шага):**
  $$x_2 = \frac{18 - 2,14 - 2 \cdot 2,892}{10} = \frac{18 - 2,14 - 5,784}{10} = \frac{10,076}{10} \approx 1,008 \quad (\text{в таблице: } 1,00760)$$
  $$y_2 = \frac{25 - 2 \cdot 1,008 - 2,892}{10} = \frac{25 - 2,016 - 2,892}{10} = \frac{20,092}{10} \approx 2,009 \quad (\text{в таблице: } 2,00928)$$
  $$z_2 = \frac{35 - 1,008 - 2 \cdot 2,009}{10} = \frac{35 - 1,008 - 4,018}{10} = \frac{29,974}{10} \approx 2,997 \quad (\text{в таблице: } 2,99738)$$

* **Сверка:** Результаты совпадают со второй строкой таблицы из методических указаний.

### 3. Почему шаг Зейделя не дороже базовых итераций?

* Количество арифметических операций за один шаг не меняется, так как расчётные формулы остаются прежними.
* По памяти метод не требует дополнительного массива для нового вектора приближений — значения перезаписываются сразу поверх старых.
* В коде программы вместо записи в отдельный массив `xNext[i]` и чтения из старого `x[j]` все операции чтения и записи выполняются в одном рабочем массиве `x`.

### 4. Ловушка порядка строк

После перестановки первых двух строк система принимает вид:
$$2x + 10y + z = 25$$
$$10x + y + 2z = 18$$
$$x + 2y + 10z = 35$$

* **Коэффициенты на диагонали:** $2$, $1$ и $10$.
* **Проверка диагонального преобладания:**
  * Первая строка: $|2| < |10| + |1| \implies 2 < 11$ (нарушено).
  * Вторая строка: $|1| < |10| + |2| \implies 1 < 12$ (нарушено).
  * Третья строка: $|10| > |1| + |2| \implies 10 > 3$ (выполняется).
* **Прогноз:** Из-за отсутствия диагонального преобладания в первых двух строках метод Зейделя разойдётся, а значения переменных начнут лавинообразно расти по модулю.

### 4. Цена точности (рабочая система)

```text
eps = 1E-002 -> Базовый: 6 шагов, Зейдель: 3 шагов
eps = 1E-004 -> Базовый: 10 шагов, Зейдель: 5 шагов
eps = 1E-006 -> Базовый: 14 шагов, Зейдель: 7 шагов
```

* **Сравнение:** Метод Зейделя требует ровно вдвое меньше итераций на каждом пороге точности (3, 5 и 7 против 6, 10 и 14 у базового метода).
* **Причина экономии:** Каждый шаг использует уже обновлённые на этой же итерации значения предыдущих переменных, благодаря чему вектор приближения движется к точному решению в два раза быстрее.
